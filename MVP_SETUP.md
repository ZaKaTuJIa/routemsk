## Яндекс Метрика

В ветке PR #1 установлен реальный ID владельца: ROUTEMSK_CONFIG.metrikaCounterId = 112716166.
Подключён официальный асинхронный загрузчик https://mc.yandex.ru/metrika/tag.js из документации Яндекса.
Вебвизор, карты кликов, автоматическое отслеживание ссылок, hash, ecommerce и передача заголовка отключены.
Инициализация использует defer:true; затем отправляется один hit с постоянным URL https://routemsk.ru/, пустым referer и фиксированным названием. Query/hash и исходный referrer не передаются этим вызовом; meta referrer=no-referrer также исключает HTTP Referer. Noscript-пиксель не добавлен, чтобы не обходить этот контролируемый путь.
Цели передают только ID счётчика и имя события, без дополнительных параметров. Имена файлов, содержимое СТС, номера документов и контакты не передаются кодом сайта в аналитику. Имя файла отображается только локально через textContent.
Это не обещание анонимности стороннего сервиса: обычная техническая телеметрия Метрики остаётся. В кабинете перед выпуском проверить отсутствие автоматических целей/сбора данных форм и утвердить условия обработки данных.
Документация: https://yandex.ru/support/metrica/en/code/counter-initialize и https://yandex.ru/support/metrica/en/objects/hit.

Цели типа «JavaScript-событие»:

| Идентификатор | Значение |
| --- | --- |
| telegram_click | Нажатие ссылки Telegram, не подтверждённая заявка |
| whatsapp_click | Нажатие ссылки WhatsApp, не подтверждённая заявка |
| phone_click | Нажатие номера, не подтверждённый звонок |
| sts_upload_start | Открытие выбора файла; пользователь может отменить |
| sts_upload_success | Зарезервировано; исключено из разрешённых целей до реальной доставки |

Проверка после подключения: цели видны в отладке Метрики; блокировщик аналитики не ломает ссылки или интерфейс. Успех заявки сверять с фактическим обращением.

## СТС: фактическое поведение

Файл выбирается и проверяется локально (JPG/PNG/PDF, непустой, до 10 МиБ).
Ничего не отправляется на сервер, в Telegram API или WhatsApp.
Посетитель сам открывает мессенджер и прикрепляет документ.
Выбор файла на сайте необязателен. submitStsToServer — отклоняющая запрос заглушка.
Нельзя вызывать sts_upload_success после выбора файла или клика на мессенджер.

Будущая автоматическая доставка — отдельная задача, не реализована в v0.8: серверная проверка формата/размера и безопасности файла, ограничения частоты, утверждённые правила хранения/удаления и обработки данных, защищённые серверные секреты. Ответ должен различать ошибку, принятие в очередь и подтверждённую доставку. Только подтверждённая доставка допускает sts_upload_success. Не хранить токены бота в HTML/JS и не логировать содержимое СТС.

## Юридические данные и доверие

В футере остаются честно обозначенные заглушки. Это незакрытая задача, не готовые документы.
Нужны фактический исполнитель, реквизиты, контакт для вопросов о данных, утверждённые политика и согласие с учётом реального процесса передачи через мессенджеры.
Не выдумывать адрес, ИНН, отзывы, рейтинг или юридические гарантии.
Владельцу подтвердить цены, сроки и заявления об опыте с 2014 года / парке 100 авто.
